## Improvements
Customer signup confirmation and loading states, truthful cart errors, stale delivery quote protection, checkout recovery, missing page fallback, offline notification, keyboard focus and reduced motion support. Frontend vendor bundles are separated. Offline shell caching includes compiled assets.
Database computes option prices from merchant configuration, rejects unknown/duplicate/missing required options, and rejects unavailable cart items and excessive aggregate quantities.
PayFast callback signatures include empty posted fields. Merchant, amount, session token, HTTPS URLs and callback HMAC are checked.

   Import MaverickMonoka/Shesha, use main, build command npm run build, publish directory dist.

   MOBICOM_PAY_API_KEY, MOBICOM_PAY_SESSION_SECRET, MOBICOM_PAY_WEBHOOK_SECRET, PAYFAST_PASSPHRASE.
   Generate independent high-entropy API/session/webhook secrets using secure administration.
   Configure Supabase PAYMENT_GATEWAY_BASE_URL to the deployed worker URL.
   Supabase PAYMENT_GATEWAY_API_KEY must match MOBICOM_PAY_API_KEY.
   Supabase PAYMENT_GATEWAY_WEBHOOK_SECRET must match MOBICOM_PAY_WEBHOOK_SECRET.
   Confirm payment-webhook uses the configured matching secret before testing.
   Never place secrets in frontend environment variables, source control or chat.
3. Current worker configuration is SANDBOX with test merchant credentials and IP checks skipped.
   Complete a sandbox payment, cancellation, retry and duplicate-webhook test against real services.
   Before live payments use live PayFast merchant credentials/passphrase, PAYFAST_SANDBOX=false and PAYFAST_SKIP_IP_CHECK=false.
4. Browser visual/accessibility testing, authenticated end-to-end ordering and real payment verification have not passed in this environment.

## Remaining engineering limitations
This package targets the existing Supabase project. Historical migrations do not fully recreate its live schema from an empty database; do not treat it as a portable database bootstrap.
Stock is checked at checkout; stock reservation across multiple simultaneous orders still needs validation.
The gateway has no persistent session ledger. Database payment transition protections exist, but end-to-end duplicate callback testing remains required.
Security advisors flag authenticated callable privileged RPCs. Inspected merchant, driver and admin RPCs include ownership/role checks; the notices are not a completed penetration test.
No production-ready or world-class claim is made until these release gates pass.

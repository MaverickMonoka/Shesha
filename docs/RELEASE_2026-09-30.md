# SHESHA release — 30 September 2026

## Fixes delivered
- Server-authoritative option pricing, atomic cart additions and quantity updates.
- Confirmed checkout total: a price change rolls checkout back and sends the customer to review the cart.
- Stock holds expire after 45 minutes. Payment retries recheck and renew stock availability.
- Payment stock accounting sums every variant and decrements only once per paid order.
- Duplicate events are checked again after locking. Additional or late payments require reconciliation.
- Real paid receipts are retained even after cancellation. Stock shortfalls block merchant fulfilment until an administrator restocks and resolves them.
- Customer policy helpers work; approval fields and payment records cannot be edited directly.
- Merchant payout details are excluded from public/client reads.
- Merchant and branch onboarding is atomic; driver applications cannot self approve.
- Unapproved stores cannot publish products to public shoppers.
- Driver offers expose the required order details; suspended and busy drivers cannot accept jobs.
- Realtime publications cover orders, notifications, driver locations, dispatch offers and products.
- Signup confirmation, cart failures, address submission, stale delivery quotes, missing pages, offline warnings and focus/reduced-motion behavior are improved.
- Mobicom Pay v0.3.2 rejects unsigned trailing fields, unknown statuses, unsafe amounts/URLs and oversized payloads. Provider/downstream calls have timeouts. Live mode always enforces source IP checks.
- Payment webhook requires a verified signature, exact amount, currency and recognized status.
- Payment-session updates cannot overwrite terminal payment states.
- Supabase SDK imports are pinned. CI runs gateway, payment-session, webhook and database regressions.

- MOBICOM_PAY_API_KEY
- MOBICOM_PAY_SESSION_SECRET
- MOBICOM_PAY_WEBHOOK_SECRET
- PAYFAST_PASSPHRASE

Configure matching Supabase secrets:
- PAYMENT_GATEWAY_BASE_URL = https://mobicom-pay.pkhardware2.workers.dev
- PAYMENT_GATEWAY_API_KEY = the same secure value as MOBICOM_PAY_API_KEY
- PAYMENT_GATEWAY_WEBHOOK_SECRET = the same secure value as MOBICOM_PAY_WEBHOOK_SECRET

Use independently generated high-entropy API, session and webhook secrets.
Do not put secrets in browser code, source control or chat.
The worker currently uses sandbox/test merchant configuration.
Before live payments, supply live PAYFAST_MERCHANT_ID, PAYFAST_MERCHANT_KEY and PAYFAST_PASSPHRASE; set PAYFAST_SANDBOX=false and PAYFAST_SKIP_IP_CHECK=false.
PAYFAST_ALLOWED_IPS may override documented defaults with explicit IPs/CIDR ranges.

Complete real sandbox success, cancellation, retry and repeated-callback checks, plus mobile browser QA, before enabling live checkout.

## Security advisor notices
Supabase flags public boolean policy helpers and authenticated privileged RPCs as callable security-definer functions.
The helpers return booleans; mutating RPCs enforce session, ownership or administrator access.
Allow/deny regression tests cover these paths. This does not replace a penetration test.
Reference:
https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable
https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable

## Operational limits
Mobicom Pay remains stateless. SHESHA records payment events and flags additional payments for reconciliation; it cannot promise provider-level prevention of every duplicate charge.
Very late payments or external stock adjustments can create an inventory shortfall; the paid order is retained and blocked for operations review.
Actual concurrent-session/load testing and end-to-end provider verification remain release gates.
No production-ready or world-class claim is made before those gates pass.
